# A Go consumer of the bdd-suite module

A small workspace that uses the Go runtime the way another repository would:
the module `github.com/smartpcr/bdd-code-extension/runtimes/go` by version, with
no `replace` directive and no path into this repository (docs/packages, E3).

| Part | What it is |
| --- | --- |
| `go.mod` | The module at the release version, and `suiterun` as a tool (`go tool suiterun`). |
| `schema/actions.catalog.yaml` | Its catalog: the core imported by name (`bdd-suite:core`) and two actions, `greet.say` and `greet.shout`; `suite.schema.json` and `suite.schema.md` beside it are generated by the spec's `Build-Schema.ps1`. |
| `suites/` | `greeting.yml` (offline) and `loud.yml`, which uses `greet.shout`, an action `tests/bddsuite.tests.yaml` does not list as offline, so its tests skip unless `BDD_SUITE_ALLOW_GUARDED=1`. |
| `greeter/` | Its extension, `greeter.Extension`. |
| `cmd/suiterun/` | Its own `suiterun`: `suiterun.Main(..., greeter.Extension)`. |
| `tests/` | Its suites as `go test` tests, generated by `go generate ./...` and committed, as Go generated code is. |

There is no `go.sum` here: the module version this sample is proved against
is written locally before any tag exists, so `run-e3.ps1` writes `go.sum` in its
own copy. A project of your own runs `go mod tidy` once.

Run it (writes the module into the local file GOPROXY first):

```powershell
pwsh -File samples/consumers/go/run-e3.ps1
```

It works in `artifacts/e3/work` with a module cache of its own and the local
feed first in `GOPROXY`, then checks that `go generate` writes exactly the
committed tests, its `suiterun`'s `lint`, `list --name` and
`run --name --progress`, and `go test`: every case passes but the guarded one,
which skips; all pass with `BDD_SUITE_ALLOW_GUARDED=1`; `-run` selects one case.
