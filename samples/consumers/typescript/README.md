# A TypeScript consumer of the bdd-suite package

A small workspace that uses the TypeScript runtime the way another repository
would: the package `@bdd-suite/runtime` by version, with no path into this
repository (docs/packages, E5).

| Part | What it is |
| --- | --- |
| `package.json` | `@bdd-suite/runtime` at the release version; `npm run generate` and `npm test`. |
| `schema/actions.catalog.yaml` | Its catalog: the core imported by name (`bdd-suite:core`) and two actions, `greet.say` and `greet.shout`; `suite.schema.json` and `suite.schema.md` beside it are generated by the spec's `Build-Schema.ps1`. |
| `suites/` | `greeting.yml` (offline) and `loud.yml`, which uses `greet.shout`, an action `bddsuite.tests.yaml` does not list as offline, so its test skips unless `BDD_SUITE_ALLOW_GUARDED=1`. |
| `greeter.mjs` | Its extension, `greeterExtension`. |
| `bin/suiterun.mjs` | Its own `suiterun`: `main(argv, undefined, [greeterExtension])`. |
| `bddsuite.tests.yaml` | Its suites as `node:test` tests, generated into `tests/` by `npm run generate`. |

Until the package is on a registry, `run-e5.ps1` installs the tarball
`npm pack` makes:

```powershell
pwsh -File samples/consumers/typescript/run-e5.ps1
```

It works in `artifacts/e5/work`, proves `node_modules` holds the packed files
rather than a link, generates the tests, checks its `suiterun`'s `lint`,
`list --name` and `run --name --progress`, and `node --test` with the
runtime's JUnit reporter: every case passes but the guarded one, which skips;
all pass with `BDD_SUITE_ALLOW_GUARDED=1`; a name pattern selects one case.
