# A Rust consumer of the bdd-suite crate

A small workspace that uses the Rust runtime the way another repository would:
the crate `suiterun` by version, with no path into this repository
(docs/packages, E4).

| Part | What it is |
| --- | --- |
| `Cargo.toml` | `suiterun` at the release version (with `testing`) as a dependency and a build-dependency; its own `suiterun` binary; one `harness = false` test target. |
| `schema/actions.catalog.yaml` | Its catalog: the core imported by name (`bdd-suite:core`) and two actions, `greet.say` and `greet.shout`; `suite.schema.json` and `suite.schema.md` beside it are generated by the spec's `Build-Schema.ps1`. |
| `suites/` | `greeting.yml` (offline) and `loud.yml`, which uses `greet.shout`, an action `tests/bddsuite.tests.yaml` does not list as offline, so its trials are ignored unless `BDD_SUITE_ALLOW_GUARDED=1`. |
| `src/lib.rs` | Its extension, `GreeterExtension`. |
| `src/main.rs` | Its own `suiterun`: `suiterun::main_with(..., GreeterExtension)`. |
| `build.rs`, `tests/suites.rs` | The suite list generated at every build, and the harness that runs it. |

Until the crate is on crates.io, `run-e4.ps1` builds a copy of this folder with
`[patch.crates-io]` naming the crate `cargo package` produced:

```powershell
pwsh -File samples/consumers/rust/run-e4.ps1
```

It works in `artifacts/e4/work`, proves with `cargo metadata` that the packaged
crate is the one compiled, then checks its `suiterun`'s `lint`, `list --name`
and `run --name --progress`, and `cargo test`: every case passes but the
guarded one, which is ignored; all pass with `BDD_SUITE_ALLOW_GUARDED=1`;
`--exact` selects one trial.
